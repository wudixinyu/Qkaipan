Three cooperating Node singletons form a layered data stack with strict dependency direction: `save_db.gd` (SaveDB) owns the on-disk profile at `user://save.json` — loading, default schema, migration (`_migrate_gacha`, `_normalize_cards`), wallet/cards/team/presets/progress/gacha state, and emits `saved`/`loaded` signals; `game_db.gd` (GameDB) is a pure read-only config layer that loads `res://data/game_data.json` into memory and exposes typed query methods for elements, combat/board, rarities, characters, codex, growth, gacha pools/probabilities/pity/costs, adventure stages, formation rules, and monsters; `realm_db.gd` (RealmDB) is the runtime derivation layer that composes the two above — it calls `GrowthCore.stats_of` plus `GameDB.star_bonus_table()` to compute final card stats, evaluates declarative synergy rules from `GameDB.synergies()` (cond types: member_count, row_count, role_count, element_count, rarity_count, char_ids, distinct_elements) and applies mul/add/battle-mode effects per unit, then builds roster reports, counter hints, and showcase lineups. Dependency direction is one-way: RealmDB → GameDB + SaveDB; SaveDB reads config only via GameDB defaults; GameDB never touches SaveDB or disk beyond its own JSON load.
