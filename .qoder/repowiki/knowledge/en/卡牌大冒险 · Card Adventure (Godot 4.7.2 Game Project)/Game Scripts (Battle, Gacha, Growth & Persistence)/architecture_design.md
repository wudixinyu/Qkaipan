Scripts are organized as Godot autoload singletons rather than scene-scoped modules, so any scene can access them globally. Two major subsystems coexist at this level: (1) the battle layer — `battle.gd`/`battle_ctx.gd` expose an autoloaded context that `stage_select.gd` invokes to launch fights, while `battle_core.gd` runs deterministic ATB simulation and `card_view.gd`/`card_fan.gd`/`formation.gd` render it; (2) the data/growth layer — `game_db.gd` and `realm_db.gd` load static JSON configs, `save_db.gd` persists player profiles, `growth_core.gd` derives runtime stats from cards and synergies, and `gacha.gd`/`gacha_sys.gd` drive card acquisition while writing back to `save_db.gd`. Cross-cutting concerns like stamina (`stamina.gd`) gate progression into `stage_select.gd`, which is the central hub that composes these autoloading services to move between menus, battles, and collections.
