The module is a flat collection of Godot `.gd` entry points plus Python helpers, organized by purpose rather than layer:

- Scene builders: `build_*.gd` (battle, formation, gacha, main_menu, stage_select) extend `SceneTree`, load JSON from `res://data/game_data.json`, programmatically construct the scene tree via `ui_kit.gd`, then `pack()` + `ResourceSaver.save()` to `res://scenes/*.tscn`. Each file documents its fixed 1920×1080 layout zones in comments.
- UI primitives: `ui_kit.gd` (`class_name UIKit`) is a stateless `RefCounted` helper library providing static factories for panels, labels, buttons, gradient textures, and anchor/position helpers; all build scripts consume it through `const UI := preload("res://tools/ui_kit.gd")`.
- Smoke-test harness: `smoke_*.gd` are headless `SceneTree` drivers that wait ~4 frames, dynamically `load()` a suite under `suites/` (e.g. `battle_suite.gd`), call `suite.run(self)`, and `quit(0|1)` based on the returned `{passed, failed}` counters. Suites cover four layers — config consistency, battlefield geometry, combat math/determinism, and scene skeleton/interaction — and back up/restore `user://save.json` around execution.
- Screenshot/preview tools: `shot_*.gd` and `preview_monsters.gd` attach to `RenderingServer.frame_post_draw`, render the built scene, grab `get_root().get_texture().get_image()`, and save PNGs under `res://shots/`.
- Python asset pipeline: `init_game_db.py` parses `data/db/schema.sql` split by `-- @db:` markers into two SQLite databases (`game_cfg.db` static config, `player_save.db` player save), seeds them with inline `CONFIG_*` tuples, and supports `--force/--demo/--verify`. Other `.py` files (`prep_assets*`, `make_icons.py`, `clean_char_alpha.py`, `apply_*.py` under `_inspect/`) handle image preprocessing and data patching.

Dependency direction is one-way: build/smoke/shot scripts depend on `ui_kit.gd` and on runtime game code loaded at runtime (`scripts/battle.gd`, `scripts/battle_core.gd`, autoloads like `BattleCtx`/`SaveDB`); nothing in the production `scripts/` or `scenes/` depends back on `tools/`.
