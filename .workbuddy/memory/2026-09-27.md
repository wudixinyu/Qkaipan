# 2026-09-27 工作日志

## 数据库落地：MySQL 设计文档 → SQLite（data/db）

### 决策
- **两库物理拆分**：`data/db/game_cfg.db`（静态配置，只读、可热更）+ `data/db/player_save.db`（玩家存档，WAL、可写）。
  理由：SQLite 文件即库，热更配置时可完全不动存档。
  代价：跨库无法建 FOREIGN KEY，`hero_id/item_id/stage_id` 等指向配置表的列靠应用层校验；
  临时联表用 `ATTACH DATABASE`。
- 时间统一 `datetime('now','localtime')`（SQLite 原生 CURRENT_TIMESTAMP 是 UTC，不能用）。
  体力恢复 / 挂机收益这类时间差计算后续改存 Unix 整数时间戳更稳。
- `updated_at ON UPDATE CURRENT_TIMESTAMP` 用触发器替代（`trg_player_updated` / `trg_formation_updated` / `trg_gacha_updated`，带 `WHEN NEW.updated_at = OLD.updated_at` 守卫）。
- 建号用触发器兜底：`trg_player_after_insert` 自动补 `tb_player_stage` 一行 + 三类空阵型（type 1/2/3）。
  → 应用层不再需要写这三条初始化记录（踩过的坑：seed 用 UPDATE 会静默无行，改 UPSERT）。
- 主键一律 `INTEGER PRIMARY KEY AUTOINCREMENT`，避免删档后 guid 被复用导致装备引用串号。
- 配置表补全了原文档只被引用的表：`tb_cfg_skill / tb_cfg_item / tb_cfg_chapter / tb_cfg_monster_group / tb_cfg_drop_group / tb_cfg_gacha_pool`。
- `tb_cfg_stage` 增加 `stage_no / pre_stage_id` 支撑关卡引导线。

### 产物
- `data/db/schema.sql`：单一源文件，用 `-- @db: cfg` / `-- @db: player` 标记分区，头部含完整 MySQL→SQLite 类型/语法映射表。
- `tools/init_game_db.py`：按标记切分 schema、建两个 db、灌配置、`--demo` 灌演示存档、`--verify` 自检。
  用法：`python tools/init_game_db.py [--force] [--demo] [--verify]`
  - 配置库每次强制重建；存档库默认**不覆盖**（保护联调存档），需 `--force`。
  - 自检覆盖：integrity_check / foreign_key_check / JSON 合法性 / updated_at 触发器 / 建号补行 / 级联删除。
- 已灌配置：hero=4 skill=8 item=8 chapter=3 stage=22 monster_group=3 drop_group=9 gacha_pool=1。
  4 张卡与 `assets/art/characters/` 的 knight/priest/pyromancer/ranger 一一对应，卡框按品质映射 `assets/art/frames/frame_{r,sr,ssr,ur}.png`。
  22 关 / 3 章（8+7+7），与「22 张卡 / 3 关 / 第 1 关 8 张卡」的关卡规模设定一致。

### 注意点
- `tb_player_item."count"` 是 SQLite 内置函数名，必须双引号引用；若嫌麻烦可全局改名 `item_count`。
- Godot 侧：`godot-sqlite` GDExtension；配置库 `db.path="res://data/db/game_cfg.db", read_only=true`，存档库必须落 `user://`（res:// 在导出后只读）。

### Godot 4.7 踩坑（都已在代码注释里留痕）
- **「类型由 Variant 推导」在 4.7 里是编译 ERROR**（不是警告）→ 所有 `var x = dict.get(...)` 必须显式标注类型，否则 autoload 编译失败并级联出 "Identifier not found: SaveDB"。
- **`--script` 模式下，被直接加载的脚本在编译期看不到 autoload 全局名** → 解决办法：build 脚本把工作从 `_initialize()` 挪到 `_process()`，并用运行期 `load()` 而非 `preload()`；冒烟测试拆成「无 autoload 的瘦 runner + 延迟加载的 suite」两层。
- **`set_anchors_preset()` 不清 zero offset** → `fill()` 必须显式把四个 offset 归零，否则 size 与 anchor 叠加成双倍（CardFan 变 3840×2160）。
- **HBoxContainer 的 minimum_size = 子节点最小宽之和**，会顶开给定宽度 → 卡面三围条改手工 1/3 等分定位。
- **ThorVG 不支持 SVG 的 `fill-rule="evenodd"`** → 空心图标（齿轮/邮件/金币/迷宫）改用 `stroke` 画。
- `Tween.set_delay()` 属于 Tweener，不属于 Tween，要挂在每次 `tween_property()` 的返回值上。

### 卡面与扇形排布（本轮主要修正）
- `CardView` 所有内部坐标由 `rarity.inner_rect` 反推，四种卡框开口差异不会让徽章/品质/星级/名牌/三围跑出内腔。
